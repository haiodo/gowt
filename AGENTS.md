# gowt agent guide

Start from the map, then the layer docs:

- [docs/code-map.md](docs/code-map.md) - which files implement each feature (primary, platform, tests, examples).
- [docs/agents.md](docs/agents.md) - facade API idioms: how to write gowt code.
- [docs/internals.md](docs/internals.md) - repository layout, translator flow, build gates.

Generated vs hand-written:

- Never edit files with a `Code generated by j2go` / `Code generated by girgen` header; they are rewritten by `make gen`. Change the translator (`tooling/j2go`, `tooling/girgen`, `tooling/webkitgen`) or the source pins instead, and commit generator and regenerated output together.
- Hand-written code lives in `*_manual*.go` files and in the packages outside `swt/`, `internal/cocoa`, `internal/win32`, `internal/gtk`, `internal/webkit` (facade root, `look`, `icons`, `svg`, `rx`, `gfx`, `webview`, `qa`, `browser` bridge). In generated packages only `*_manual*.go` is hand-written, including in `jface` (the layout/widget factories are translated).
- After a feature change, update its row in [docs/code-map.md](docs/code-map.md).

Agent limits:

- Run at most 2 agents at the same time, including agents resumed from an earlier session.
- Subagents must not spawn other agents.
- The coordinator must not start new tasks while all slots are busy.
